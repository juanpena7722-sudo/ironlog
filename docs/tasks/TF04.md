# TF04 — Data layer on the API (kg canonical)

- **Status:** Verified, PR #14 awaiting owner approval
- **Branch:** feat/tf04-api-data-layer
- **Date:** 2026-11-11

## Summary

Every page now reads and writes its data through the API instead of `localStorage`.
`src/store.tsx` holds TanStack Query hooks and mutations for workouts, foods, body, health and
goals. Weights are kept in kg and lengths in cm; `src/units.ts` converts them to the user's
display unit (`Goals.unit`, stored by the API) on every page, input and chart. A 401 from any
data request ends the session. The Vite dev proxy now keeps the browser's `Host` header, so
sign-in and other `POST`s work through `npm run dev`.

## Notes

- Cycle 1 failed: **Clear all logs** sent `DEFAULT_GOALS` when `GET /goals` had failed or not
  yet loaded, which would overwrite the user's goals and unit. Fixed in `da75445`: the button
  and its confirm are disabled until the goals load, and the request sends the saved goals.
  Regression test: `src/pages/Settings.test.tsx`, `cannot clear all logs while GET /goals %s`.
- The Vite dev proxy used the string shorthand, which sets `changeOrigin`; the API then saw
  `Host: localhost:3000` with `Origin: http://localhost:5173` and rejected every `POST` with 403
  in development. The proxy config now keeps the `Host` header. The API's check is unchanged.
- The unit preference is `Goals.unit` in the API, so it follows the account. Saving targets
  after switching to kg stores the shown value (for example 45.4 kg instead of 45.36 kg), within
  the 0.1 tolerance.
- The Diet page has no edit control (as before TF04); entries are added, re-added and deleted.
- The old `localStorage['ironlog:data']` key is not read or removed; the one-time import is TF05.
