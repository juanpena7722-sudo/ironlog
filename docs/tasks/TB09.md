# TB09 — Hardening, gateway and production stack

- **Status:** Verified, PR #10 awaiting owner approval
- **Branch:** feat/tb09-hardening-gateway
- **Date:** 2026-11-11

## Summary

Hardens the API (security headers with CSP, a global rate limit, body limits, log redaction,
graceful shutdown, OpenAPI at `/docs` outside production only) and adds the production stack: a
non-root API image that migrates on start, a Caddy gateway that serves the built frontend and
proxies `/api/v1/*`, and a Compose file where only the gateway publishes ports.

## Notes

- `dist/` is bind-mounted into the gateway, so run `npm run build` before starting the stack.
  The `.dockerignore` excludes `dist/` safely: the API image builds `server/dist` itself and the
  gateway reads `./dist` through the bind mount, not the build context.
- `POSTGRES_PASSWORD` must be URL-safe because Compose places it in `DATABASE_URL` unescaped.
- Known and accepted: on Linux, the Docker host itself can reach the containers' bridge IPs. The
  API and database are still not published on any host port.
- Through the gateway, Caddy's security headers overwrite the ones `@fastify/helmet` sets on API
  responses (for example `X-Frame-Options: DENY` instead of `SAMEORIGIN`).
- The `npm warn install-scripts` messages during `npm ci` were there before TB09.
