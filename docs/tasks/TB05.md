# TB05 — Food log API

- **Status:** Verified, PR #6 awaiting owner approval
- **Branch:** feat/tb05-foods-api
- **Date:** 2026-11-08

## Summary

Adds the food log API under `/api/v1/foods`: list by date range, recent distinct foods, create,
replace and delete. Every route requires a session and only touches the current user's entries.
Bodies and responses use the shared `FoodEntrySchema`. The `:id`, date-range and date-format
helpers that workouts already used now live in `server/src/routes.ts` and are shared by both
plugins.

## Notes

- Release added one regression test: the gate showed the branch in `/recent` that reads a second
  batch was not covered (`foods.ts` line 64). With it, `foods.ts` has 100 % lines and branches.
- `/recent` returns full `FoodEntry` objects (the newest entry for each name), not just names, and
  looks at all dates, not only the list's 30-day window.
- `/recent` reads batches until it has `limit` distinct names, so a user with many repeats of the
  same few foods causes several queries. The list has no pagination; the date range is the only
  limit on its size.
- There is no `GET /foods/:id`; the spec does not ask for one.
- The default `from` is 30 days before the current UTC day and applies even when only `to` is given,
  as for workouts.
