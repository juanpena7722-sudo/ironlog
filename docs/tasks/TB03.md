- **Status:** Verified, PR #4 awaiting owner approval

- **Date:** 2026-11-08

## Summary

Adds user accounts and sessions to the API. Users register and log in with email and password
(argon2id). The session is an HS256 JWT in an `HttpOnly`, `Secure`, `SameSite=Strict` cookie.
`app.requireAuth` protects routes and sets `request.userId`. A global Origin check, a per-IP
rate limit on auth routes and log redaction protect the endpoints.

## Notes

- The default goals in `server/src/auth.ts` duplicate `DEFAULT_GOALS` from `src/store.tsx` (the
  values match). Follow-up: move them to `shared/`.
- The seed user `demo@ironlog.local` still has an empty `passwordHash` and cannot log in (login
  returns 401). Out of scope for TB03.
- Sessions are stateless: logout and account deletion clear the cookie but do not revoke the
  token. `requireAuth` looks the user up after verifying the token and returns 401 if the user
  was deleted (`DELETE /api/v1/auth/account › rejects the old session on a protected route after
deletion`). Follow-up: a token from before logout stays valid until it expires (no revocation).
- The rate limit counts per route and per `request.ip`. Fastify's `trustProxy` is not set, so
  behind the gateway every client would share the gateway's IP. Follow-up for TB09.
- `GET /auth/me` is also limited to 10 requests/min per IP. TF03 should take this into account.
- The Origin check compares `Origin` with `request.host` exactly. A `Host` header with an explicit
  default port (for example `ironlog.test:443`) does not match `https://ironlog.test` and gets 403. Browsers omit default ports, so this matters only if the gateway rewrites `Host`; TB09
  should confirm.
- `argon2` is pinned to `^0.41.1` because later releases need a newer glibc than 2.28 (see
  `setup.md`).
