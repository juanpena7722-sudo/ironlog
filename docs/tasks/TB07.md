## Summary

Adds the goals API under `/api/v1/goals`. `GET` returns the current user's goals, or the default
goals if none are stored (without creating a row). `PUT` validates a full `Goals` body with the
shared `GoalsSchema` and upserts it. `targetWeight` is always kg; `unit` is only the display
preference. Both routes require a session and only touch the current user's goals.

## Notes

- A throwaway probe (not committed) checked that `PUT` returns 200 at every upper limit, 400
  just above (`targetWeight` 2000.01 and 1e308), 400 for a string number and a `null` body, and
  403 with a foreign `Origin`; unknown fields such as `userId` are ignored.
- `targetWeight` is stored as `Decimal(6,2)`, so it is rounded to 2 decimals (`82.555` is
  returned as `82.56`).
- `GET` does not create a row for a user without one; the first `PUT` creates it. Register
  already creates the row with `DEFAULT_GOALS`.
- `PUT` takes only a full `Goals` body; there is no partial update (`PATCH`).
